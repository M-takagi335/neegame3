# ストーリーエディター

「neegame3」の選択式ストーリーゲーム制作ツールです。日本語の編集画面から、セリフ、選択肢、パラメータ分岐、画像演出を組み合わせたゲームを制作できます。ランタイムは HTML・CSS・JavaScript で動作します。

## 起動方法

Node.js 22 以降で、リポジトリのルートから次を実行します。依存パッケージのインストールは不要です。

```sh
node serve.mjs
```

表示された [ローカルURL](http://127.0.0.1:4173/neegame3/) をブラウザーで開いてください。ローカルサーバーも GitHub Pages と同様にサブディレクトリから配信します。出力したゲームHTMLはファイルを直接開けます。

## 制作とプレイ

1. 作品一覧で「新しい作品」を選ぶか、初回に作成されるサンプル「放課後、鐘が鳴るまで」を編集します。
2. キャラクターやパラメータを登録します。タイムライン下部からセリフを続けて入力でき、各ブロック間の「＋」から任意のブロックを挿入できます。
3. 選択肢の詳細で表示条件、選択条件、複数のパラメータ変動、分岐先を設定します。その場で分岐先のシーンを作成できます。分岐マップから各シーンへ移動できます。
4. 画像素材を登録し、背景や立ち絵、表情を設定します。登録済みの素材をタイムラインとキャラクター管理の両方で参照できます。
5. 「テストプレイ」では作品の先頭、シーン、選択中のブロックから開始できます。デバッグ欄でパラメータや移動先を確認し、直前の状態に戻れます。
6. 作品設定でノベル形式とチャット形式を切り替えます。「制作データを出力」で画像を含むJSONを保存し、「ゲームHTMLを出力」で単体で配布できるHTMLを生成します。JSONは作品一覧から読み込めます。

制作データ、画像、プレイのセーブは IndexedDB に保存します。配色の設定は LocalStorage に保存します。通常プレイとテストプレイは別々のセーブを使用します。単体HTMLのセーブは、そのファイルを開いたブラウザーの LocalStorage を使用します。ファイルURLの保存可否と保存範囲はブラウザーに依存します。画像や作品はアプリから外部サービスへ送信されません。ブラウザーのサイトデータを削除する前や端末を移行する際は、制作JSONを保存してください。

## 実装上の判断

- 作品一覧をホームと兼用し、編集画面にシーン、タイムライン、詳細、各管理タブを配置しています。スマートフォンでは編集ペインを切り替えます。
- シーンの終了時に移動先が空の場合は、簡易の終了画面を表示し、エラー確認には警告を出します。条件分岐と無条件移動の空欄は設定エラーです。
- シーンに未指定の背景・立ち絵は引き継ぎます。立ち絵はシーンごとに引き継ぎを無効にして、表示なしから開始できます。
- Undo・Redo は開いている作品の編集セッションで最大80操作を保持します。素材の登録解除も履歴で戻せるよう、画像本体は作品を削除するまで保持します。
- 静的な分岐検査に加え、開始シーンから最大300状態を試行します。警告は具体的な試行結果を示し、全てのパラメータの組み合わせを網羅するものではありません。プレイ中も、入力なしの自動処理が1000件を超えると安全に停止します。
- 初期版の分岐マップは閲覧と移動に対応します。マップ上からの直接編集、および仕様の将来拡張項目は対象外です。

## テスト

```sh
npm test
```

自動テストは、数値・真偽値の変更、上下限、AND・ORの判定順、選択肢の表示・選択条件、連打防止、シーン移動と合流、デバッグの巻き戻し、ループ制御、サンプルの三つの結末を検証します。

実装時の確認結果は、自動テスト6件がすべて成功です。デスクトップ版Chromeでは、作品作成、キャラクターと好感度の同時登録、10種類のブロックの途中挿入、分岐マップ、保存と再読み込み、Undo・Redo、テストプレイのセーブ・ロードと巻き戻し、画像付きJSONの復元、不正なJSONの拒否、チャット形式の単体HTMLの再生を確認しました。390pxと820pxのエミュレーションでレスポンシブ表示も確認しました。iPad・スマートフォンの実機と GitHub Pages の本番URLでの確認は未実施です。

## GitHub Pages での公開

1. 公開したい変更を既定ブランチ（このリポジトリでは `main`）に反映します。
2. GitHub の **Settings → Pages** で **Deploy from a branch** を選択します。
3. `main` と `/ (root)` を指定して保存し、デプロイ完了後に Pages のURLを開きます。

静的ファイルは相対パスを使用します。ビルドとAPIキーは不要です。ローカル版と公開版はオリジンが異なるため、制作データを共有する場合はJSONを使います。

## ファイル構成

- `js/model.js` と `js/sample.js` — 制作データとサンプル
- `js/app.js`、`js/editor.js`、`js/forms.js` — アプリ、編集画面、入力フォーム
- `js/engine.js` と `js/player.js` — 共通実行ロジックとプレイ画面
- `js/storage.js` と `js/export.js` — IndexedDB、JSON検証、入出力
- `js/graph.js` と `js/validation.js` — 分岐マップと問題検出
- `css/` と `tests/` — スタイルと自動テスト
